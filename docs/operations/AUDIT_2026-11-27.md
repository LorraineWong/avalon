## Live SEO observations

Read-only checks of 42 URLs covered home, the language-query home, all 36 named
content pages and four guide aliases. Home/content pages returned 200 with a
canonical. The slashless guide roots returned one normal 301 to their slash
versions. `/how-to-play/` returned 200 with a meta refresh and script redirect;
an infinite HTTP loop was not reproduced. Responses identified GitHub Pages
(`Server: GitHub.com`). The historical 15 November Search Console failure is
therefore not evidence of a still-active server redirect loop.

The source and generated site retain one canonical per page, reciprocal nine-
language content-page hreflang families, correct HTML language tags and existing
localized titles/descriptions. Home intentionally has one canonical URL: its
`?lang=` variants are application preferences, not nine additional indexable
home pages. Named content routes select their language from the path. The
sitemap still contains 37 intended canonical URLs; robots does not block them.
No duplicate SEO pages or blanket `noindex` rules were added. All guide text,
including collapsed content and the player table, exists in static HTML.

Local Wrangler parsed all 120 generated rules. Every source returned 301
directly to a real 200 destination; none chained or looped. Incoming query
parameters were retained. For example, `/how-to-play/?utm_source=party&lang=zh`
redirected to `/how-to-play/en/?utm_source=party&lang=zh`; the explicit destination
path controls this content page's language.

**Deployment boundary:** GitHub Pages does not consume Workers' `_redirects`.
Its fallback remains a static meta refresh, now without a conflicting script.
The direct HTTP redirects were verified against the existing Workers local
configuration, not deployed on the live domain. Activating equivalent edge
redirects or routing the domain through the configured Workers deployment needs
a separate owner-authorized deployment/configuration step. See the official
[Workers static-assets redirect format](https://developers.cloudflare.com/workers/static-assets/redirects/).

Search Console was not accessed. The four “Page with redirect” exclusions may
be appropriate aliases. The five discovered/unindexed and two crawled/unindexed
URLs were not supplied, so their individual causes cannot be established. The
32 indexed pages in the historical report do not justify creating/removing
pages to match an indexing count. After an authorized release, recheck the
specific URL list and request validation for the redirect error.

## Security and reliability boundaries

Firebase authenticates users and limits game/secret writes to the host and
seat/presence writes to their owning user. Existing rule-expression tests check
these boundaries; they are not proof of deployed rules. Room holders can read
public state and ciphertext. ECDH P-256/AES-GCM private role payloads and the
host-only encrypted master are retained; role maps are published at game end.
No new unencrypted role map, private-player event fields, raw-input HTML sinks
or service-account credential was introduced. The Firebase Web API key and
App Check site key are public configuration, not private credentials.

The host browser remains trusted and can inspect/alter its game. A hostile host,
modified clients, simultaneous host tabs and a trusted authoritative server are
not solved by this architecture. Nickname/capacity enforcement is client/host
validation, not a database uniqueness constraint. The JSON-string room schema
does not let Firebase rules validate every game transition or role rule. Host
unexpected loss still requires the original browser identity/private key to
return; an explicit transfer re-encrypts recovery data. Clearing storage or
losing the host device cannot be repaired by UI changes.

Expiry remains a marker enforced by clients, with no scheduled server deletion.
Rooms whose host never returns can remain stored. No Firebase Spark/billing or
background-cleanup changes were made. Full production multiplayer, mobile
software keyboards and native OS share sheets need device/production review.
The new manual-copy fallback was tested in short desktop-browser viewports.
