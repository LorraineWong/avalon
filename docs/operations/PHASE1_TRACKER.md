## 建议的运营与隐私做法（尚未启用）

Batch 3 优先选现有免费、轻量的页面分析与低频 HTTP/资源监控。
首页监控只代表静态页面可用，不能代表 App Check 或联机成功。
不采用高频匿名注册/开房探针，不设置任何付费试用或自动续费套餐。
通知目的地与第三方账户由负责人明确指定，不从登录账号猜测邮件收件人。

Batch 5 事件方案先采用最小字段：事件名、客户端版本、粗粒度语言/设备类别和
时间桶；字段最终以批准方案为准。不要收集 nickname、uid、完整 room code、
URL hash、角色、投票、笔记、错误对象中的 token/请求 URL。
去重口径须分别定义“房间级”和“玩家级”，再来一局要区分新一局，避免五个
客户端把同一个开局统计五次。免费页面分析不一定支持自定义游戏事件，不为
追求事件数建立公开可写统计库。机器人影响和不采集身份造成的准确性限制必须说明。

反馈入口优先评估现有 GitHub Issues 模板：Bug、翻译、网络、手机问题；
需说明提交 Issues 要 GitHub 账号，与游戏无需注册是两回事。
如果要求反馈也免登录，再比较免费表单的隐私、垃圾防护和移动体验。
安全问题继续走私密漏洞报告，不引导用户把角色或房间密钥发到公开 Issue。
